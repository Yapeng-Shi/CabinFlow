## 可复现构建步骤

首次准备依赖：

```bash
sudo apt-get install build-essential flex bison dwarves libssl-dev libelf-dev cpio qemu-utils rsync
```

在上述构建目录中执行（`source/` 是完整归档解压目录，`out/` 是新目录）：

```bash
cp source/Microsoft/config-wsl out/.config
source/scripts/config --file out/.config --module CAN_VCAN \
  --set-str LOCALVERSION -microsoft-standard-WSL2-cabinflow-vcan
make -C source O="$PWD/out" olddefconfig
make -C source O="$PWD/out" -j8 bzImage modules
make -C source O="$PWD/out" INSTALL_MOD_PATH="$PWD/modules" \
  INSTALL_MOD_STRIP=1 modules_install
make -s -C source O="$PWD/out" kernelrelease
```

遵循该 tag 的 [官方构建说明](https://github.com/microsoft/WSL2-Linux-Kernel/blob/linux-msft-wsl-6.6.87.2/README.md)。

## 实总线首次暴露的软件缺陷

首次集成失败于独立 ECU 初始状态查询，不能算通过。源码核对发现后端与 ECU
把 `CAN_ERR_FLAG` 放入 `CAN_RAW_FILTER` 的 data mask；内核 `can_rcv_list_find()`
因此将订阅注册到 `RX_ERR`，普通数据帧不能到达。
修复只移除两处 mask 的该位，保留 `CAN_SFF_MASK | CAN_EFF_FLAG | CAN_RTR_FLAG`。
默认错误帧订阅仍关闭，codec 的 ERR/EFF/RTR 拒绝也保留，没有协议放宽或重试。
依据 [SocketCAN 官方说明](https://docs.kernel.org/networking/can.html#can-filter-usage-optimisation)
与 [固定内核实现](https://github.com/microsoft/WSL2-Linux-Kernel/blob/427645e3db3a8896714f22a3d3fe0c3f7b317ad4/net/can/af_can.c#L369)。

Sol `max` 独立审查先确认修复设计；新增集成负例使用当前事务号、相反状态的合法
EFF/RTR/wrong-ID 帧，在正确 ACK 前断言异步请求仍等待、原状态不变，再验证正确 ACK 完成。
修复后真实 vcan 集成已通过。这解释了为什么 codec/测试替身通过不能替代内核 socket 集成。
