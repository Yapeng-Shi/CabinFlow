# CabinFlow Demo 实施计划

> 先做出一个能听、能答、能播放、能取消的离线座舱语音 Demo。

更新日期：2026-10-03。用户已确认改为 Demo 优先，取代此前“先完成全部 Runtime 迁移收尾、暂停模型工作”的安排。实现和验证进度见第 9 节，不把计划本身当作完成证据。

2026-10-02 进一步批准：先搭完整系统并解耦组件，方便之后替换和升级。单个模型的答案质量不再作为系统集成前置门槛；停止继续围绕 0.6B 算术错答扩展诊断。此调整不批准实际更换当前模型、不引入自动回退，也不把旧失败改成通过。

## 1. 当前目标与范围

面向智能座舱交互开发岗位，用现有 C++/Linux Runtime 支撑一个小而完整的语音应用。重点是“用户操作 → 后端处理 → 可见状态 → 可听回答”，不继续把通用 Runtime 建设当作项目主线，也不以复刻车企私有系统为目标。

首版只做：

- 单会话、单活跃任务；输入一段短 WAV 或一条文本，不做持续录音、唤醒和多乘员。
- 真实 ASR → Dialogue/LLM → 真实 TTS；文本输入明确跳过 ASR，不是 ASR 失败后的替代路径。
- Qt/QML 展示转写、回答、任务状态和错误，播放回答，提供取消按钮。
- 沿用已有空调开/关意图，增加一个明确标记的 FakeVehicle 空调开关演示；不连接真实车辆。
- 2026-10-03 用户继续执行确认可视化扩展：Qt/QML 的 2.5D 驾驶员视角，增加左前车窗全开/全关；空调出风与玻璃升降只展示 FakeVehicle 回执，不增加真实车辆接入。
- 少量固定用例、基本耗时/资源记录和一段可复现演示。

首版不做：RAG、AAOS/AIDL/Binder/VHAL、vcan/SOME-IP、RK3576、复杂场景、补偿、多区域权限、流式上传/首 token 展示、自动恢复，以及全量历史能力迁移。后置不等于删除或已完成，原源码和证据保留。

## 2. 复用什么，不重做什么

| 技术 | 首版用途 |
|---|---|
| C++、Linux、多线程、RAII | 后端业务、现有 Target 队列/worker、生命周期与资源释放。 |
| TCP、Protobuf | Qt 前端与后端的唯一接入路径，沿用现有 Gateway 和业务 schema。 |
| Sherpa / ONNX Runtime、llama.cpp | x86 CPU 上的真实 ASR、TTS 和 LLM，沿用已锁定模型与库。 |
| Qt/QML | 操作界面、任务状态和回答播放；不承担模型推理。 |
| CMake、CTest、GDB、ASan/TSan | 沿用已有构建测试；用 GDB/日志定位实际问题，sanitizer 覆盖受影响路径。 |
| ZeroMQ | 保留已有实现与测试；首版后端内部用现有进程内队列，不为用 ZeroMQ 拆多进程。 |

开发与首版运行目标采用同一个 WSL Linux 环境，Qt 通过 WSLg 显示和播放；先实际验证 Qt 窗口与声音可用，未验证前不宣称已支持。暂不引入 Windows 前端或 Android↔WSL 时钟转换方案。

```text
Qt/QML 前端
  └─ TCP + RuntimeMessage Protobuf
       └─ 一个 C++ Demo 后端（装配现有 Gateway / Runtime）
            ├─ WAV → ASR → Dialogue/LLM → TTS → 回答音频
            ├─ 文本 ─────→ Dialogue/LLM → TTS → 回答音频
            └─ 已有明确空调意图 → FakeVehicle → 实际执行回执
```

这是一条前后端产品路径，两个明确的输入类型；没有失败后换模型、切 fake 或改协议的分支。后端节点在同一进程中复用 Runtime，模型调用先在现有 worker 内同步完成，不新增 Runtime 异步完成框架。

ASR、LLM、TTS 在 Agent 内以最小 C++ 端口解耦，具体 Sherpa/llama 实现由应用在启动时构造注入。节点与编排不包含具体 SDK 类型；以后更换模型路径或适配器不修改 Runtime、前端协议或重写业务链。只装配一个明确实现，不做插件、工厂注册或失败后切换。组件执行成功、模型语义质量、人工可听分别验收。

QML 负责展示，C++ 负责网络与业务状态。界面不能因连接、等待模型或退出而卡住；同步推理不等于在 GUI 线程执行推理。

- 模型文件与推理库已经锁定：Sherpa 1.11.3 CPU shared 上游包、llama.cpp b6500 本地 CPU 构建。不要重新从选型/下载/版本锁定开始。[依赖审计](../agent/docs/model-dependency-audit.md)。
- ASR 有两次加载/解码结果，但缺参考转写评估；TTS 有两次结构/非静音结果，但缺人工听验；LLM 已加载，却在两组配置下未通过 `1+1 → 2` 的答案验收。整体模型烟测仍失败，三个组件均未接入真实 Runtime 链。[烟测记录](../agent/docs/model-smoke-results-20260930.md)。

## 4. 实施顺序：每一步都能看见结果

步骤 1 与组件接入可并行，Runtime 缺口只在实际使用相关入口前关闭。先完成可替换组件的 CLI 集成切片（文本与 WAV 两个明确入口），随后接唯一 TCP/Qt 产品路径；CLI 不是第二条生产接入或回退路径。参考转写、模型答案和听验独立记录，不阻塞系统装配；最终质量结果仍须如实报告。

| 步骤 | 要做的最小工作 | 这一步完成的证据 |
|---|---|---|
| 1. Demo 必需的 Runtime 小收尾 | 复用已有一次性启停；仅关闭下面列出的实际入口/安全缺口。 | 受影响测试通过，正常退出、错误和任务关联正确；不要求账本全部 verified。 |
| 2. 解耦并接入真实组件 | 最小 ASR/LLM/TTS 端口，具体 SDK 适配器与业务节点分离；应用构造注入。 | 节点/编排不依赖具体模型 SDK；测试替身能验证失败和取消，真实适配器能运行。 |
| 3. 跑通真实输入→回答 WAV | 逐个接真实节点，做最小后端装配入口，复用现有身份和消息；先文本，再 WAV。 | 真实推理和 WAV 输出、trace/work 可串联；执行与答案质量分开，不硬编码回答。 |
| 4. 接 Qt/QML 和播放 | 选择 WAV、文本输入、开始/取消、转写/回答/状态/错误显示、播放。 | 前后端连通，界面不卡；用户能操作完整一轮并听到回答。 |
| 5. 座舱模拟与可视化 | 空调开/关及获准新增的左前车窗开/关调用 FakeVehicle；2.5D 界面展示回执后的出风/玻璃状态。 | 状态与动画由回执驱动，重复设置不翻转；未知、失败、取消和断连不伪造动作。 |
| 6. 固定用例和展示 | 运行少量成功、取消、错误用例，保存计时/资源记录和演示视频。 | 命令可复现，结果和未完成边界清楚；不追求复杂评测平台。 |

### 步骤 1：Runtime 只收尾这些

- 外部首条数据应指向 work 所属 Unit：已有批准，接前端前实现并验证；同 work 内部跨 Target 的既有规则不变。
- 非法业务 payload/final：确认最小拒绝与重投合同，修正会污染当前任务的准入状态问题；不引入通用预解析注册表或 Ledger 回滚框架。
- 输出关联保持到本次实际最终结果/明确失败/取消清理，不因上游 handler 返回就丢掉后续 TTS 音频；只服务当前同步节点链，不声称支持任意异步输出。
- 安全退出、队列满显式拒绝、取消与错误能通过当前 Demo 路径验证；出现死锁、悬空回调或错误任务归属必须修，不因赶 Demo 绕过。

上述入口可用后冻结 Runtime 扩展。旧 TCP/ZMQ 样例的完整迁移、正式 daemon、安装脚本补全、全进程历史内存保留等不阻塞短时单任务 Demo；保留限制，不能声称长期稳定或全进程内存有界。

### 步骤 2～3：组件解耦，先系统集成

沿用当前已锁定模型与版本接入系统，保留失败日志；不再调提示词或 CPU 开关追求单条算术题通过。当前质量局限不阻塞组件装配。以后模型/库的具体替换单独确认并一次性切换，不自动试其他模型、不留下多后端回退。

模型端口明确区分成功、非法输入、推理失败和取消；SDK 失败不冒充 Runtime 的 invalid payload，也不返回空结果继续下一阶段。固定逻辑身份使用 `asr.primary`、`dialogue.primary`、`llm.primary`、`tts.primary`，不绑定模型名。保留用户原文/ASR 转写，Router 的固定意图回执不是 LLM 问题。

先实现 Agent 内可复用编排和 CLI；阶段输出不等于 worker 已退出，取消抑制晚到结果，等待实际完成后再清理。Gateway/Qt 的最终音频与清理通知合同在接前端前落实，不把 CLI 集成算成 TCP 全链成功。

固定几段有许可的短中文语音，记下参考转写、预期回答关键内容、文件格式和哈希。先完成单轮、非流式回答，不要求首 token、分句并行合成或连续对话记忆。

命令、数据路径和节点放在 Agent；Runtime 不依赖 ASR/LLM/TTS、Qt 或车辆业务。不重命名现有模块，不新增插件/配置中心；只补运行当前后端所必需的装配。

### 步骤 4：界面只做一屏

- 输入区：选择短 WAV，或明确选择文本输入。
- 展示区：转写、回答、空调模拟状态、当前处理阶段、错误信息。
- 操作区：开始、取消、播放/停止；一个任务未完成清理时不接受第二个任务。
- 当前阶段：空闲、处理中、取消中、已完成、已取消、失败；这是 UI 展示，不预设新增协议枚举。
- 窗口关闭：由外部控制线程处理取消/停止和资源释放；worker 不直接调用 Runtime::stop()，不新增异步 stop API。

只发完整短输入，沿用支持的 WAV 格式和现有 4 MiB 帧体上限；检查整个编码帧体而不只算 WAV 大小。超限/不支持格式明确报错，不做流式上传或自动转码猜格式。

取消立即停止当前播放，并通知后端协作取消。若当前推理调用不能立即中断，就保持“取消中”，等待实际处理/清理完成再显示“已取消”；期间不接新任务，晚到回答、音频和车辆动作不得作为有效新结果。不能只换标签就声称所有推理已经停止。

音频返回格式、实际完成/取消清理通知及最小 UI 请求字段在接这一屏前按现有 Protobuf 确认；不新建双协议或用 Registry 的 Exit 状态冒充 handler 已退出。每次新任务创建新 work，不复用取消后的 work ID。

### 步骤 5：座舱特点小而真实

先做“打开空调 / 关闭空调”，后续用户已批准扩展“打开左前车窗 / 关闭左前车窗”的模拟状态和 2.5D 可视化；不扩其他车窗、温度/风量、10 属性、权限框架或场景补偿。规则路由决定明确动作，LLM 负责一般问答，不从模型随口说的“已打开”推断执行成功。

车辆状态以 FakeVehicle 执行回执为准；重复开或关只是设为相同状态，不使用 toggle。取消未执行动作；已经完成的动作保持已发生的事实，不自动回滚。错误和不支持意图要明确可见。

本阶段已确认最小输出合同：`VoiceTaskResult.vehicle` 携带 `simulated`、`climate_on`
和 `action_applied`，不放进 result oneof。成功、失败、取消都携带当前模拟状态与本次动作
事实；TTS 失败或动作后的取消不撤销已执行状态，不播放过期回答。后端装配显式初始化
空调为关，前端收到回执前或断连后显示未知，不从 LLM 文本推断车控。

可视化扩展的最小合同：

- 首版新增规则只精确识别“打开左前车窗”“关闭左前车窗”；不把泛指“车窗”猜成左前，也不改旧语音参考或空调规则。
- FakeVehicle 启动时显式设置空调关、左前车窗关；独立 set 操作不影响另一属性。
- `VehicleResult` 新增字段 4 `optional bool left_front_window_open`，所有已准入终态必须写入；Qt/CLI 必须检查存在性，缺字段显式失败，不能把 Protobuf 默认 false 当成已确认关闭。仓库内调用方一次性更新，不提供旧客户端/报告兼容路径。
- 每条任务的 `action_applied` 仍表示这次单一动作是否已执行；动作与取消继续使用现有任务锁线性化。取消先到不执行，动作先到不因取消/TTS 失败回滚。
- 座舱组件位于现有前端 `CockpitScene.qml`，只读 C++ 已验证状态；处理期间显示最近回执/等待，未知不展示为关。动画仅为展示过渡，不表示真实电机进度。
- 继续同一 Gateway/Router/FakeVehicle/TTS/TaskResult 路径，Runtime 不扩展；Qt Quick 原生绘制，不引入 3D 引擎、图片生成依赖、AAOS 或 CAN。
- 验收覆盖重复开关、空调/车窗独立、一般回答不车控、动作前/后取消、TTS 失败保留事实、必填回执存在性、旧 work 隔离、未知/断连以及真实 TCP/Qt 截图。语音识别失败与人工听验仍单独记录。

## 5. Demo 完成标准

全部满足再叫“完整 Demo”，前几步完成不提前写成全链成功：

架构集成里程碑与下面的最终体验验收分开：模型错答可以作为已知限制进入可运行版本，但不能因此把语义正确、人工可听或固定用例质量标为通过。

1. 不依赖云端推理，真实 WAV 经 ASR/LLM/TTS 返回语义正确、人工可听的回答。
2. Qt/QML 能完成输入、转写/回答展示和播放；处理时按钮与窗口保持响应。
3. 取消能停止播放、取消后端工作，正确区分取消中与已清理；旧结果不污染后续任务。
4. 缺模型、非法 WAV、超限消息、连接失败和推理失败显式可定位，不回退假结果。
5. 打开/关闭空调和左前车窗改变的只是模拟状态；界面与动画显示实际回执，不冒充真实车控或电机进度。
6. 一条后端启动命令、一条前端启动命令和现有构建测试命令可复现；输出目录/输入样本明确。
7. 受影响测试通过，至少完成一次正常退出与任务中退出检查；记录实际 sanitizer 范围。

## 6. 简单评测与学习

不建设评测平台。先登记 5 个短语音成功用例，覆盖一般问答、空调开和关；每个重复 3 次，逐次保存参考转写、回答/车辆结果、是否可听及失败原因。15 次是固定验收规模，实际执行记录见第 9 节；运行完成不等于语义或听验通过。

另外各演示一次处理中取消、播放中取消、坏 WAV、缺模型/坏配置、后端断连。人工听验与自动断言分开记录，不把 ASR 进程退出 0 当作转写正确。

耗时只记录已经实现的 ASR、LLM、TTS、输入到回答文件完成和实际播放开始；模型加载耗时单独记。保存设备/OS、模型库版本、输入、样本数、并发 1、起止边界及 CPU/内存观测口径。首版先报告原始值和汇总，不宣称稳定 P95、量产性能或目标硬件结果。

每完成一步，只补三点学习记录：数据怎么流、问题怎么定位、为什么选择这个简单方案。最终给出运行说明和 2～3 分钟操作视频，不先写长篇架构/面试材料。

- 旧 D1～D9 是历史设计问题索引，不再作为一次性必须全部完成的清单。一次性启停复用既有批准；只有本轮实际使用的非法 final、首条准入和取消/结果关联需在对应步骤解决。Pause、worker 发起 stop、通用异步与长期资源政策不使用、不声称支持。
- [目录计划](RUNTIME_DIRECTORY_STRUCTURE.md)仍管理模块边界；协议/状态沿用 [ADR](../runtime/docs/adr/)，变更公开接口前只确认这一步需要的最小合同。
- [迁移账本](../runtime/docs/capability-migration.md)仍管理旧能力状态；只有 verified 或用户明确批准 approved-drop 才可删除。Demo 优先不批准任何代码删除，不把后置项批量标完成。
- 既有第一周、模型与 Runtime 验证记录保留原日期和范围。本次不覆盖失败结果，不修改旧证据来适配新目标。
